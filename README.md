# A股三市场情绪指标系统

实时计算 **A股全市场 / 创业板 / 科创板** 三套独立情绪指标（0~100），
识别极端恐慌/极端过热，保存每日历史快照，并通过历史回测验证
极端情绪信号在 T+0~T+2 内形成阶段顶部/底部的命中率。

## 环境要求（重要，先看这条）

**必须使用 Python 3.10+（实测 3.13）。** 本项目源码含中文，用 Python 2 运行会直接报：

```
SyntaxError: Non-ASCII character '\xe8' in file run.py on line 1,
but no encoding declared
```

如果看到这个报错，**不是代码问题**，而是 `python` 命令指向了 Python 2。
用下面命令确认：

```bash
python --version     # 若输出 Python 2.7.x，就是命中了这个坑
py --version         # 应输出 Python 3.x
```

此时把下文所有 `python run.py ...` 换成 `py run.py ...` 即可，例如：

```bash
py run.py update
py run.py serve --port 5000
```

**为什么会这样**：Windows 查找 PATH 时**系统 PATH 优先于用户 PATH**。
若 `C:\Python27` 残留在系统 PATH 里，即使用户 PATH 中已装了 Python 3.13，
`python` 仍会解析到 2.7。彻底解决需以管理员身份从系统 PATH 中删除
`C:\Python27`（或把 Python 3 的目录加到系统 PATH 更前面），
在那之前用 `py` 启动器最省事。

## 快速开始

> **不想敲命令？** 装完依赖后直接双击项目根目录的
> **`每日更新.bat`**（更新数据）和 **`运行项目.bat`**（打开网页）即可，
> 详见下方「每日更新 & 运行脚本」。

```bash
pip install -r requirements.txt

# 1. 全量构建（首次需下载全部个股日线，约 30~60 分钟；之后每日增量更新很快）
#    加速技巧：可用多进程分片下载补齐缺口
#    python scripts/download_shard.py --shard 0 --n 6 --source sina   # 多开几个进程
python run.py update                      # 三个市场全部更新+计算+存快照
python run.py update --market CHINEXT     # 只更新创业板
python run.py update --limit 100          # 冒烟测试：只用前100只股票

# 2. 参数自动优化（最近1年为样本外，优化只用更早数据；walk-forward 验证）
python run.py optimize --market A_SHARE
python run.py optimize                    # 三个市场分别独立优化

# 3. 历史回测（使用当前激活模型版本参数）
python run.py backtest --market CHINEXT --sample oos    # 样本外
python run.py backtest --market CHINEXT --sample full   # 全历史

# 3.5 波段信号模型回测（新增独立模块；update 每天也会自动刷新 full 样本）
python run.py swing                          # 三市场 × 5套模型，T+0~T+10 阶段低点/高点
python run.py swing --market CHINEXT --model A B --sample oos   # 子集/样本外

# 4. 启动 Web 界面
python run.py serve --port 5000
# 浏览器打开 http://127.0.0.1:5000
```

> 上面列出的命令多数是"可选项/子集"，不是每次都要跑：
> `update` 不带 `--market` 已覆盖三个市场；`--market CHINEXT` 只是子集；
> `optimize` 不带参数即三个市场分别优化；`backtest --sample oos/full` 只是两种视图。

## 每日手动使用（无定时任务时）

如果没有跑定时任务，每天想打开网页看最新指标，需要两步：

**步骤 1：拉取当天数据并计算情绪快照（每天只需跑一次）**

```bash
# 增量更新三市场当天数据 + 计算当日情绪分数（数分钟；行情缺口的日期会顺延补齐）
python run.py update
```

**步骤 2：启动 Web 服务（前台运行；想停掉用 `Ctrl+C`）**

```bash
python run.py serve --port 5000
# 浏览器打开 http://127.0.0.1:5000
```

一条命令把两步串起来（适合 PowerShell / bash 写进快捷方式）：

```bash
# PowerShell (Windows) —— 若 python 指向 2.7，用 py 代替（见开头"环境要求"）
py run.py update; py run.py serve --port 5000

# bash / Git Bash
py run.py update && py run.py serve --port 5000
```

### 常见使用模式

- **只想看盘前当前数据、不想启动网页**：`python run.py update`，
  输出里会打印每个市场的当日日期、分数、级别，例如
  `[A_SHARE] A股 2026-09-17 情绪 28.3（恐慌）[V2]`。
- **只想看历史页面、数据今早已 `update` 过**：直接 `python run.py serve --port 5000`
  即可，`serve` 只读 `sentiment.db`，不动行情缓存。
- **端口被占用**：换端口 `python run.py serve --port 5001`（地址同步改成 5001）。
- **后台常开网页、每日单独 `update`**：开一个终端窗口跑 `serve` 不关，
  另开一个终端每天跑 `update`；跑完 `update` 之后刷新浏览器就能看到新数据。
- **首次 / 较长时间没跑过**：`update` 会按缺口顺延补齐最近的行情，所需时间视
  缺失天数而定（正常 1 天通常几十秒）。

## 每日更新 & 运行脚本（scripts/）

### 项目根目录：四个双击即用的入口

不想记命令的话，直接用根目录这四个（Windows 双击 `.bat`，其余双击 `.sh`）：

| 根目录脚本 | 干什么 |
|---|---|
| **`每日更新.bat`** | **每日更新**（Windows 双击） |
| **`运行项目.bat`** | **启动网页** http://127.0.0.1:5000（Windows 双击） |
| `每日更新.sh` | 每日更新（Linux / macOS / Git Bash） |
| `运行项目.sh` | 启动网页（Linux / macOS / Git Bash） |

**日常用法就两步**：先双击 `每日更新.bat` 等它跑完（几分钟），再双击 `运行项目.bat` 打开网页。

### scripts/ 下的完整脚本

| 文件 | 用途 |
|---|---|
| `scripts/daily_update.py` | 每日更新主脚本：拉行情 → 算情绪 → 刷波段信号 |
| `scripts/daily_update.bat` / `.sh` | Windows / Linux 版更新脚本（根目录入口转发到这里） |
| `scripts/start_web.bat` / `.sh` | 启动 Web 界面（前台运行，Ctrl+C 停止） |
| `scripts/install_daily_task.ps1` | 注册 Windows 计划任务，每天自动更新 |
| `scripts/crontab.example` | Linux/macOS 的 cron 配置示例 |
| `scripts/download_shard.py` | 首次全量构建时的多进程分片下载加速 |

### 一键更新（命令行版）

```bash
# Windows
py -3 scripts/daily_update.py

# Linux / macOS / Git Bash
./每日更新.sh
```

相比直接 `python run.py update`，这个脚本多了四件事：

1. **失败自动重试**（默认 2 次，间隔 30s）—— 数据源偶发抽风不会导致整天漏数据；
2. **日志落盘**到 `data/logs/daily_update_YYYYMMDD.log`，定时任务下也能事后排查；
3. **单实例锁**——上一次还没跑完时不会重复触发（进程被杀留下的死锁会自动接管）；
4. **可选 `--git-push`**——更新成功后自动把当日快照 commit 并推送到 GitHub。

常用参数：

```bash
py -3 scripts/daily_update.py --market CHINEXT      # 只更新创业板
py -3 scripts/daily_update.py --retries 3           # 失败重试 3 次
py -3 scripts/daily_update.py --timeout 7200        # 单次 update 超时改成 2 小时
py -3 scripts/daily_update.py --skip-weekend        # 周六周日直接跳过
py -3 scripts/daily_update.py --git-push            # 更新后提交并推送快照
py -3 scripts/daily_update.py --dry-run             # 只打印将要执行的命令
```

### 启动网页

```bash
# Windows：双击根目录 运行项目.bat；改端口就 运行项目.bat 5001
./运行项目.sh                    # 端口 5000

```

### 定时自动跑

**Windows（计划任务，普通权限即可）：**

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_daily_task.ps1            # 默认每天 18:30
powershell -ExecutionPolicy Bypass -File scripts\install_daily_task.ps1 -Time 19:00
powershell -ExecutionPolicy Bypass -File scripts\install_daily_task.ps1 -GitPush    # 跑完自动推送

schtasks /Query  /TN "A股情绪指标-每日更新" /V /FO LIST   # 查看上次运行结果
```

> 默认 18:30 是因为 A 股 15:00 收盘，日线数据通常 15:30~17:00 后才在数据源就位。
>
> 若安装脚本报「未找到可用的 Python 3」：它会依次尝试 `py` 启动器、
> `C:\Windows\py.exe`、`python`/`python3`、以及 `%LOCALAPPDATA%\Programs\Python` 下的
> 安装目录 —— 都找不到才报错。某些被安全软件接管 PATH 的终端里 `Get-Command` 会失灵，
> 此时脚本仍能靠 `C:\Windows\py.exe` 兜底。找到后会自动校验版本 ≥ 3.10，
> 避免命中 PATH 里残留的 Python 2.7。

**Linux / macOS（cron）：** 参考 `scripts/crontab.example`，`crontab -e` 粘贴即可。

> 脚本用 `sys.executable` 启动子进程，即"你用哪个 Python 跑脚本，就用哪个 Python 跑 update"。
> 若机器上 `python` 指向 Python 2 或没装依赖的环境，请显式用 `py -3`（见开头「环境要求」）。

## 迁移到新电脑

**状态全部落在 `data/` 目录的文件里，只要整个项目目录（含 `data/`）拷过去，
就不需要重新全量构建、重新优化或重新回测。**

| 内容 | 位置 |
|---|---|
| 个股/指数日线缓存（约 5000 个 parquet） | `data/cache/stocks/`、`data/cache/index/` |
| 因子表（三市场） | `data/factors/*.parquet` |
| 优化后的模型版本（参数/激活标记/命中率） | `data/sentiment.db` → `model_version` |
| 每日情绪快照 | `data/sentiment.db` → `sentiment_snapshot` |
| 回测运行与信号明细 | `data/sentiment.db` → `backtest_run` / `backtest_signal` |

新电脑上的最小步骤：

```bash
# 1. 复制整个项目目录（必须包含 data/）
# 2. 只有这一步必须重跑
pip install -r requirements.txt

# 3. （可选）增量补齐最新几天行情，很快；不带参数即三个市场
python run.py update

# 4. 启动界面
python run.py serve --port 5000
```

- `serve` 只读 `sentiment.db`，不碰 parquet 缓存，所以拷完依赖直接 `serve`
  就能看到与旧电脑一致的页面，第 3 步可暂时省略。
- `optimize` 可跳过：V2 参数与 `is_active=1` 已落库，`update`/`backtest`
  会优先使用激活版本，不会退回 V1 初始权重。
- `backtest` 可跳过：回测页读库中的历史 run 记录。
- `data/cache/stock_list.parquet` 缓存有效期仅 1 天，首次 `update` 会自动
  重新拉取股票列表（需联网），属正常行为。
- 配置中的数据路径是相对项目根目录解析的，换盘符/路径不受影响。

**如果只拷代码、不带 `data/`**（例如只 `git clone`），则必须重新构建：

1. `python run.py update` 会全量下载 4 年日线（约 30~60 分钟），
   可用 `scripts/download_shard.py` 多进程分片加速。
2. **`optimize` 必须重跑**，否则库里没有激活版本，系统会按
   `config/default.yaml` 的 V1 初始权重计算，下文"当前版本实测结果"中的
   V2 数字不再成立。且权重为随机搜索（`weight_random_trials`），重跑不保证
   复现完全相同的 V2 参数与命中率 —— 若要原样复现，必须带上 `data/sentiment.db`。
3. `backtest` 需重跑才会产生回测页所需的数据。

## Web 页面

界面为深色金融终端风格，遵循 A 股惯例（**红 = 上涨/过热，绿 = 下跌/恐慌**）。
页面中**带虚线下划线的术语**鼠标悬停（手机上点一下）会弹出大白话解释，
全部术语见 `/glossary`。

| 页面 | 内容 |
|---|---|
| `/` 情绪概览 | 三市场情绪分数/状态/趋势/极端信号/样本外命中率；卡片刻度条标出当前生效的极端阈值 |
| `/history` 情绪历史 | 最近7天/30天/2个月/3个月曲线（三市场对比，极端信号+波段信号标记可点击）+ 每日明细表 |
| `/swing` 波段信号 | 三市场当前是否进入极端区域、各波段模型触发状态、近期信号生命周期 |
| `/swing/backtest` 模型回测 | 每套波段模型 T+0~T+10 命中率、信号明细、时间分布、年度/牛熊震荡表现 |
| `/swing/compare` 模型对比 | 三市场 × 各模型横向对比（只展示客观数据，不排名） |
| `/backtest` 情绪回测 | T+0/T+1/T+2 分别命中率、累计命中率、信号明细、失败案例、模型版本 |
| `/glossary` 术语对照表 | 全部术语的大白话解释 + 口径修正说明（为什么数字变小了） |

**波段信号模型（新增独立模块）**：原情绪指标只负责描述市场情绪且保持固定不变；
模型A~E（纯情绪极端 / 极端+情绪反转 / 极端+指数确认 / 极端+宽度确认 / 综合）
分别读取情绪分数，研究极端情绪（≤10 / ≥90）之后 T+0~T+10 个交易日内是否形成
阶段性低点/高点（最低/高点后反弹/回撤 ≥ 3% 确认）。各模型独立回测、独立统计，
系统不做排名、不提供买卖建议。

## 系统结构

```
config/default.yaml      全部关键参数（权重/阈值/过滤规则/回测定义/搜索空间）
run.py                   CLI 入口
sentisys/
  data/        数据源(akshare 腾讯/新浪)、股票池过滤、多线程增量更新
  factors/     六大因子：涨跌家数/涨跌幅分布/涨跌停炸板连板/成交额/市场宽度/指数
  engine/      因子→历史分位子分数→加权总分；状态/历史分位/趋势/背离
  backtest/    阶段顶底数学定义、信号判定、T+0/1/2 统计、样本量校验
  swing/       波段信号模型（新增）：5套模型定义、T+0~T+10 窗口评估、统计与落库
  optimize/    阈值×反弹幅度网格 + 因子权重随机搜索 + walk-forward + 版本落库
  storage/     SQLite：每日快照 / 模型版本 / 回测运行 / 信号明细(含失败案例) / 波段信号
  web/         Flask 界面
data/          本地缓存（个股日线 parquet + sentiment.db）
```

## 关键设计

**情绪分数**：六大因子原始值 → 过去 250 个交易日分位 × 100 得到子分数
（反向指标取负值分位，方向统一：越高越热）→ 按权重加权合成 →
合成值再做一次自身 250 日滚动分位映射得到最终 0~100 分。
最终分数近似均匀分布：score ≤ 10 即过去一年中最差的 10% 交易日，
极端阈值因此具有明确语义，三套指标各自适应自身市场特征。
（副作用：250日分位 ≈ 分数本身，20/60/120 日分位仍有区分度。）

**阶段底部（数学定义）**：交易日 t 收盘价满足 `zone` 模式价格位置条件
（≤ 前 `pivot_left` 日极值 ×(1+`pos_tol`)），且之后 `confirm_window` 个交易日内
最大收盘涨幅 ≥ `rebound_pct`。顶部镜像。

> **重要（2026-09-18 口径修正）**：`rebound_pct` 已固定为 **3%**，并从优化搜索空间中
> **彻底移除**；`pos_tol` 同样固定为 2%。理由见下文「口径修正记录」。
> 它们现在等价于「判卷标准」，只允许在 `config/default.yaml` 手工修改，
> 修改后需重跑 `optimize` 与 `backtest`。

**防过拟合**：最近 1 年为样本外，优化过程不可见；训练期按时间分 3 段做
walk-forward 稳定性检验；目标函数取恐慌/过热两方向的较小值并惩罚分段波动；
样本数不足（默认 <5）时明确显示"样本不足，暂不能验证90%命中率"。

**防未来函数**：情绪计算只用当日及历史数据；顶/底判定中的右侧窗口仅用于
事后验证标签，不参与信号生成。

**涨跌停推导**：不依赖第三方涨停池，按各板块涨跌停规则
（主板10%/创业板20%/科创板20%）由日线数据数学推导涨停/跌停/炸板/连板。
使用前复权数据，单日涨跌幅与真实一致，不影响判定。

**数据异常**：当日可统计股票数低于股票池 30% 标记 `abnormal`；
数据源不可用时保留上一交易日记录，不伪造当日数据。

## 口径修正记录（2026-09-18）

### 问题：判卷标准被交给优化器，导致命中率系统性虚高

`backtest.rebound_pct`（判定阶段底部所需的最小反弹幅度）原本被纳入优化搜索空间
（`optimize.rebound_pcts: [0.01, 0.015, 0.02, 0.03, 0.05]`）。
优化目标本身就是「命中率越高越好」，于是三个市场**全部收敛到最松的一档 1%**。

后果：1% 反弹阈值下，**44%~52% 的交易日都被判定为"阶段底部"**。
底部标签遍地都是，信号自然"百发百中"——但这与预测能力无关。

量化对照（A股全市场）：随机挑一天、往后 3 天内撞上"阶段底部"标签的概率高达 **69.7%**，
而系统报告的样本外命中率是 88.2%，**真实优势仅 +18.5pp**。

### 修正

1. `config/default.yaml`：删除 `optimize.rebound_pcts` 与 `optimize.pos_tols`；
   `backtest.rebound_pct` 固定为 **0.03**、`pos_tol` 固定为 **0.02**。
2. `sentisys/optimize/optimizer.py`：阶段 1 由「阈值 × 反弹 × 容差」四层嵌套降为
   **仅阈值**两层；顶/底标签预计算一次后全程复用。

### 修正后结果（V3，激活版本）

样本外底部命中率与「瞎猜基线」对照：

| 市场 | 底部命中率 V2→V3 | 瞎猜基线 1%→3% | 真实优势 V2→V3 |
|---|---|---|---|
| A股全市场 | 88.2% (n=17) → **45.5%** (n=11) | 69.7% → 23.2% | +18.5pp → **+22.3pp** |
| 创业板 | 92.3% (n=13) → **73.3%** (n=15) | 51.5% → 36.6% | +40.8pp → **+36.7pp** |
| 科创板 | 93.3% (n=15) → **66.7%** (n=18) | 59.7% → 35.6% | +33.6pp → **+31.1pp** |

**结论：报告数字大幅下降，但真实优势基本不变 —— 信号确实携带有效信息，
此前 90% 是松标准吹出的泡沫。**

### 补充：光看"真实优势"还不够，必须做显著性检验

把优势幅度列出来会让人以为"正数就是有用"。但样本少时，一次两次的偶然就能造成
很大的幅度差。因此 `summarize()` 增加了一组统计字段，对每个方向做**二项检验**
（观察成功数 vs 瞎猜基线的期望）并给出 Wilson 95% 置信区间与一句话结论。

**统一使用双尾检验**：我们并没有先验理由假定信号一定正向 —— 命中率显著低于基线
同样是重要信息（说明信号是反的），单边检验会漏掉这种情况。

样本外完整结论（V3，双尾 p）：

| 市场 / 方向 | 命中率 | 瞎猜基线 | 真实优势 | 双尾 p | 95% CI | 结论 |
|---|---|---|---|---|---|---|
| A股 见底 | 45.5% (n=11) | 23.2% | +22.3pp | 0.174 | 21%~72% | 方向对，但**不够显著** |
| A股 见顶 | 16.7% (n=6) | 23.1% | −6.4pp | 0.415 | 3%~56% | 与瞎猜无法区分 |
| 创业板 见底 | 73.3% (n=15) | 36.6% | +36.7pp | **0.009** | 48%~89% | ✅ **显著，可用** |
| 创业板 见顶 | 50.0% (n=2) | 44.2% | +5.8pp | 0.624 | 9%~91% | 样本太少，无法判断 |
| 科创板 见底 | 66.7% (n=18) | 35.7% | +31.0pp | **0.015** | 44%~84% | ✅ **显著，可用** |
| 科创板 见顶 | 55.6% (n=9) | 42.7% | +12.8pp | 0.651 | 27%~81% | 与瞎猜无法区分 |

**修正两处此前过度解读的地方**：

1. A股见顶 16.7% 看起来"真实优势为负"，但双尾 p=0.415、CI 宽达 3%~56% ——
   **正确说法是"样本太少，区分不了有效与运气"，而不是"这个信号没用"**。
2. 初版用单边检验时 A股见底 p=0.087 看着"接近显著"，改双尾后 p=0.174 ——
   **并不显著**。真正站得住的目前只有**创业板见底**和**科创板见底**。

### 第二角度：前瞻收益（比二元命中率功效高得多）

"命中/未命中"只保留了一比特信息，n=11 时几乎测不出任何东西。
因此补了一组连续指标：信号后 1/3/5/10 个交易日的**平均涨跌**，
与"随机挑一天"的分布做**置换检验**（20000 次重抽样，纯 numpy，无需 scipy）。

样本外（正数 = 信号方向对了）：

| 市场 / 方向 | T+1 | T+5 | T+10 | 最显著的一档 |
|---|---|---|---|---|
| A股 见底 | +0.56% (平时 +0.03%) | +0.76% (+0.14%) | +1.24% (+0.30%) | T+1，双尾 p=0.070，仍不显著 |
| A股 见顶 | −0.23% (−0.03%) | −0.61% (−0.14%) | +0.19% (−0.30%) | 均不显著 |
| 创业板 见底 | **+1.43% (+0.05%)** | +1.74% (+0.28%) | +1.97% (+0.56%) | **T+1，双尾 p=0.019 ✅ 显著** |
| 创业板 见顶 | +1.46% (−0.05%) | −0.79% (−0.28%) | +1.06% (−0.56%) | n=2，样本太少 |
| 科创板 见底 | +0.69% (+0.07%) | +1.36% (+0.38%) | +1.59% (+0.76%) | 均不显著 |
| 科创板 见顶 | −0.86% (−0.07%) | −2.02% (−0.38%) | −3.54% (−0.76%) | 均不显著（方向甚至偏反） |

**可读性最强的一条**：创业板发出极端恐慌信号后，
**次日平均涨 1.43%，而平时只有 0.05%**，多出 1.37 个百分点，双尾 p=0.019。

值得注意：A股见底 T+10 平均 +1.24% vs 平时 +0.30%（多 +0.94%），方向一致但
p=0.276 不显著 —— **看着不错和统计上站得住是两回事**，这正是加检验的意义。

页面（概览页、情绪回测页）会用带颜色标记的结论条 + 前瞻收益表直接显示这些判定。

### 附带修正：统一极端阈值口径

`swing` 模块原本从 `config.sentiment` 读固定阈值（≤10 / ≥90），
而「情绪概览」页与 `pipeline.py` 用的是激活模型版本调参后的阈值（如 A股 ≤3 / ≥94）——
**同一个系统里两套分数线**。

现已统一：`sentisys/swing/runner.py` 新增 `_active_params()`，
从激活版本 `params_json` 一并取权重与极端阈值，config 仅作为尚未 optimize 时的兜底；
阈值与来源版本会写入 `swing_run.params_json` 便于核对。波段页也改为显示真实生效值。

统一后波段回测（全历史，信号数因阈值收紧而减少，命中率反而提升）。

### ⚠️ 波段模型的瞎猜基线非常高 —— 命中率必须减基线才有意义

波段模型的"命中"定义较宽松：10 个交易日内出现极值、之后反向走够 3%。
**这个条件随便挑一天也经常满足**，实测瞎猜基线：

| 市场 | 见底方向瞎猜基线 | 见顶方向瞎猜基线 |
|---|---|---|
| A股全市场 | 26.0% | 25.4% |
| 创业板 | **53.5%** | **56.8%** |
| 科创板 | **53.5%** | **57.9%** |

因此"命中率 66.7%"**并不代表厉害**（创业板基线就有 53.5%）。加上基线对照与双尾
二项检验后，全部 30 个「市场 × 模型 × 方向」组合中：

- **仅 1 个统计显著**：创业板 模型B 见底 —— 73.3% vs 基线 53.5%，优势 +19.8pp，双尾 p=0.043
- **15 个与瞎猜无法区分**（p ≥ 0.05）
- **14 个样本太少**（n<5），无法判断
- **若干个命中率低于基线**，例如科创板 模型A 见底 50.0% < 基线 53.5%（−3.5pp）、
  科创板 模型D 见底 30.8% < 53.5%（−22.8pp，p=0.052）—— 这类应直接排除

> 这与前面修掉的"命中率注水"是同一类问题，只是来源不同：
> 前者是判定标准被优化器调松，这里是判定标准本身（10 日窗口 + 3%）就宽松。
> **结论：波段模型目前基本不具备统计上的预测优势，不应作为决策依据。**
> 页面（模型对比、模型回测）会显示基线列与显著性标记，绿色 ✓ 才是站得住的组合。

## 剩余待观察项

### ③ 因子权重集中度：不是 bug，是 5% 下限的产物

V3 各因子权重（A股）：distribution 33.3%、index 32.0%、limit 14.8%、volume 10.4%、
adv_decline 4.7%、breadth 4.7%。后两项贴着下限，容易误以为"被优化器抛弃了"。

实际原因在 `optimizer.py` 阶段 2：

```python
w = rng.dirichlet(np.ones(len(DEFAULT_WEIGHT_KEYS)) * 2.0)
w = np.maximum(w, 0.05)   # 防止任一因子被压到 0
w = w / w.sum()           # 归一化后实际下限略低于 5%（约 4.7%）
```

这个下限是**有意设计的**——避免某个因子被完全归零。贴着下限说明优化器确实想压低它，
但被下限拦住了。前两项合计约 65% 属于优化器的正常选择，且已通过样本外检验。

> 顺带修正一处此前的误述：`rng = np.random.default_rng(42)` **有固定种子**，
> `optimize` 是可复现的，重跑会得到相同参数。

### 候选改进（尚未实施）：目标函数用 min(恐慌, 过热) 可能不合理

`_objective()` 返回 `min(dir_scores)`，即取两个方向中**较差**的那个作为优化目标。
这会强迫优化器去提升一个可能根本没有信号的方向。

现在已经证实：三个市场的见顶方向在样本外全是 p≥0.4（与瞎猜无法区分）。
那么 `min()` 等于让一个纯噪声方向参与决定最终参数，可能拖累见底方向的表现。

**为什么现在不改**：评估这个改动需要看样本外表现，而我已经看过样本外结果了 ——
此时再据此调整目标函数，等于在检验集上做选择，会重蹈"命中率注水"的覆辙。
正确做法是重新设计训练/检验划分后再评估。**留作后续，不要现在动。**

### ④ 新股过滤：已清理死配置

`config.filters.min_history_days: 250` **从未被任何代码引用**（全局 0 处引用），是死配置。
宽度类因子（above_ma20/60/120/250）的分母为 `col.notna().sum()`
（`factors/compute.py:112`），历史不足的股票本身是 NaN，已被自动排除出分母，
因此该过滤条件本就是多余的。已从配置移除并加注释说明。

`min_list_days: 90`（`data/universe.py:45`）是有实际作用的，保留。

## 已知限制

- **顶部方向样本不足且无统计优势**（见上表），当前不建议使用。
- **样本量是主要瓶颈**：见底方向 n=11~18，见顶方向 n=2~9。
  统计检验的效力随样本增长，建议持续每日 `update` 积累数据后重新评估。
- ST 过滤基于当前股票名称（免费数据源无历史名称），历史回测中
  曾经戴帽现已摘帽的股票会被全程排除，影响可忽略但存在。
- 北交所默认未纳入（配置 `markets.A_SHARE.boards` 可加 `BJ`）。
- 90% 命中率是优化目标而非保证值；若样本外达不到，系统如实展示，
  并保留全部失败信号供迭代分析（新版本不覆盖旧版本）。
